# PEOPLE-03 authorized User Accounts read API

Status: local implementation pending real PostgreSQL 16 CI. This is a **ProjectX implementation decision** for the SCR-025 backend only. The SevenRooms screen visibly has a roster, Name, Job Title, Additional Options, Email Notifications and an Access Level filter; its backend routes, permission behavior for other roles, pagination, sorting, role precedence, search and export are unknown.

`GET /api/v1/people/accounts` requires a server-provided verified identity and selected Organization plus the active organization-scoped `user.read` capability. The default application has no OIDC/session binding and returns 401 until a trusted server integration supplies the restricted runtime pool and scope resolver. No query parameter can select an Organization or Venue. A venue-only grant does not authorize an organization roster. This intentionally leaves venue-limited roster visibility unavailable; U-002 remains unknown. No request handler uses a migration-owner connection.

The read query runs inside PEOPLE-02's authorized transaction as the non-owner runtime role, with RLS active. It includes active Organization Membership rows in the selected Organization. Response fields are only `id`, derived nullable `name`, nullable `jobTitle`, nullable `emailNotificationsEnabled` and `accessLevels`. Name joins supplied first and last names; both absent yield `null`. The notification value retains `null`, `false` and `true`. The `accessLevels` array contains sorted distinct names from active organization-scoped Role grants for that membership. It is display information, not a permission predicate. Venue roles are not silently merged or assigned precedence in this organization roster. Exact name filtering can only reduce the authorized result set.

Pagination uses ascending User UUID order, exclusive `cursor`, default `limit=25`, maximum `100` and `nextCursor` only when more authorized rows exist. Empty authorized results return HTTP 200 with `items: []` and `nextCursor: null`. Invalid query returns 400, missing trusted identity 401, missing/revoked/disabled capability 403, and internal errors use the existing safe 500 response. No client-selectable search, sorting, other endpoint, creation, edit, UI or export is added. The identifier supports future navigation but does not implement a detail API. This contract does not claim reference pagination, validation or failure behavior; U-002, U-003, FLOW-006 and Export behavior remain unresolved.
