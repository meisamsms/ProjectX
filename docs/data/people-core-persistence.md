# PEOPLE-01 persistence boundary

The visible User Accounts and Add User screens confirm user and venue access concepts, including “Create same access at other venues.” User (ENT-043) and Venue (ENT-044) are mapped reference concepts. The relationship behind that control is inferred; Organization, AuthenticatedIdentity, OrganizationMembership and VenueAccess are ProjectX implementation concepts under approved ADR-0003/0004. Their physical representation is not claimed to match the reference product.

The migration creates only organizations, venues, users, authenticated_identities, organization_memberships and venue_access. Organization and Venue names are fixture/display identifiers needed for minimum foundation records. User has no login or profile fields. Issuer/subject binds a future verified provider subject without storing tokens. Tenant ownership is constrained by composite `(organization_id, id)` keys and two VenueAccess FKs to matching membership and Venue. Partial unique indexes prevent duplicate active membership and active Venue access while allowing retained revoked history. Revocation timestamps and User disabled timestamp are independent; the database stores them but authorization enforcement belongs to PEOPLE-02. Foreign keys restrict deletion and no child record cascades. IDs are application-generated UUIDv7; they are not authority. Timestamps are `timestamptz`; the application must display UTC deliberately. Version increment remains an application operation for later tasks.

This schema does not yet have RLS or restricted runtime grants. It must not be exposed to request traffic before PEOPLE-02 isolation and authorization gates. U-002, alternate-role behavior, and FLOW-006 success/failure/cancel behavior remain unresolved.
